# HealthInformatics

An end-to-end data engineering project built on the [Fitbit Fitness Tracker dataset](https://www.kaggle.com/datasets/arashnic/fitbit). It covers data ingestion, profiling and cleaning, relational storage, cloud warehousing, containerized deployment, and automated testing.

## Reproduction Steps

### 1. Obtain the Dataset

1. Download the dataset from [Kaggle](https://www.kaggle.com/datasets/arashnic/fitbit).
2. Extract the downloaded ZIP archive. Note the path of the extracted `fitbit/` folder; it is referred to below as `{dataset_folder}`.

### 2. Clone the Repository

```bash
git clone https://github.com/bnogh123/HealthInformatics.git
cd HealthInformatics
```

### 3. Ingest the Dataset

Run the ingestion script, replacing `{dataset_folder}` with the path to your local `fitbit/` folder:

```bash
python Scripts/Localized_Ingestion.py {dataset_folder}
```

Upon completion, an `ingested_data/` directory containing the processed source files will exist in the repository root.

### 4. Clean the Dataset

```bash
python Scripts/EDA.py clean
```

### 5. Run Exploratory Data Analysis

After cleaning is complete, run the profiling routines (record counts, schema documentation, and null analysis):

```bash
python Scripts/EDA.py eda
```

## Core Relational Store (MySQL)

This stage loads the cleaned data into a MySQL database and documents its structure with an Enhanced Entity-Relationship (EER) diagram. It assumes that the ingestion, cleaning, and EDA steps above are complete.

### MySQL Setup

1. Download and install [MySQL Community Server](https://dev.mysql.com/downloads/mysql/) and [MySQL Workbench](https://dev.mysql.com/downloads/workbench/). PostgreSQL may be substituted, but the instructions below are specific to MySQL.
2. During installation, set a password for the `root` account and keep it somewhere secure.
3. Confirm that the MySQL server is running. By default it listens on `localhost`, port `3306`.

### 6. Connect to the Server

1. Open MySQL Workbench.
2. Next to **MySQL Connections**, select the **+** icon to create a new connection.
3. Enter the following, then select **Test Connection**:
   - **Connection Name:** `HealthInformatics` (or any name)
   - **Hostname:** `127.0.0.1`
   - **Port:** `3306`
   - **Username:** `root`
   - **Password:** `rootroot` (or any password)
4. Enter the password when prompted, then select **OK** to save the connection.
5. Double-click the new connection to open a session.

### 7. Upload to the OLTP Database

1. Select **File → Open SQL Script**, navigate to the project folder, and open `Scripts/DDL.sql`. Repeat for `Scripts/DML.sql`.
2. Run `DDL.sql` first, since it creates the schema and tables. In its tab, select **Query → Execute (All or Selection)**.
3. Switch to the `DML.sql` tab and execute it the same way to populate the tables.
4. In the **SCHEMAS** panel, select the refresh icon to confirm that the new database and its tables appear.

> **Note:** Run DDL before DML. The DML statements depend on the tables created by the DDL script.

### 8. Generate the EER Diagram

1. Select **Database → Reverse Engineer**.
2. Select the stored connection from step 6 and continue.
3. Select the database created in step 7 and continue through the remaining prompts, keeping the defaults unless you have a reason to change them.
4. When the wizard finishes, the EER diagram opens in a new tab. Save it with **File → Save Model** or export it with **File → Export → Export as PNG**.
